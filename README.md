## Обзор

Проект реализует автономного браузерного агента на Go. Агент использует Playwright для управления браузером и Anthropic Claude (через HTTP API) для принятия решений. Решение соответствует требованиям ТЗ:

- нет жёстко заданных пошаговых сценариев или селекторов;
- все взаимодействия строятся на универсальных инструментах (`click`, `fill`, `collect_links`, `read_page` и т.п.);
- поддерживается интерактивный режим с запросом дополнительной информации у пользователя.

## Структура проекта

```
Ai-agent-for-browser/
├── cmd/browseragent/          # CLI обвязка: парсинг аргументов, интерактивный режим, запуск оркестратора
├── internal/agent/            # Оркестратор и планировщик (Plan-and-Execute)
│   ├── orchestrator.go        # Основной цикл: LLM → инструмент → память
│   └── planner/               # Подсказки и формат взаимодействия с LLM
├── internal/browser/          # Обёртка над Playwright (navigate, click, fill и пр.)
├── internal/tools/            # Toolbox — описание инструментов, доступных модели
├── internal/llm/              # Клиент Anthropic Claude (HTTP API + ретраи)
├── internal/memory/           # Потокобезопасная память шагов агента
├── storage/                   # (опционально) сохранённые Playwright storage state
└── README.md                  # Описание и инструкции
```

## Установка и запуск

1. Установите Go 1.21+.
2. Установите Playwright зависимость (при необходимости):
   ```bash
   npx playwright install
   ```
3. Настройте переменные окружения:
   ```bash
   export ANTHROPIC_API_KEY=<ваш_ключ>
   export ANTHROPIC_MODEL=claude-sonnet-4-5-20250929   # необязательно, есть значение по умолчанию
   ```
4. Соберите бинарник:
   ```bash
   go build ./cmd/browseragent
   ```

## Интерактивное управление

Запуск агента:

```bash
./browseragent -storage storage/hh_session.json
```

После запуска программа работает в режиме чата:

```
Доступные команды: start — начать выполнение задачи, exit — завершить программу.
Введите команду (start/exit): start
Опишите задачу: Найди 3 подходящие вакансии ...
```

- `start` — переход к вводу задачи;
- `exit` — завершение работы без запуска агента.

Если указать флаг `-task`, задание будет выполнено без интерактивного режима (подходит для автоматизации).

## Управление сессиями браузера

- `-storage <path>` — путь к Playwright storage state (cookie/сессия).  
  Пример: `-storage storage/yandex_session.json`
- `-save-state <path>` — сохранить обновлённую сессию после успешного запуска.

Так можно один раз авторизоваться вручную, а затем переиспользовать сохранённые cookie.

## Логирование в формате диалога

Сообщения агента выводятся в формате:

```
user: ...          # исходная задача
agent[1]: ...      # действие и краткий результат
agent[2]: ...      # ...
```

Для «шумных» инструментов (`read_page`, `collect_links`, `collect_texts`) выводятся пометки `(данные опущены)` — это позволяет следить за ходом работы без захламления терминала. Ошибки выводятся полностью.

## Как устроен агент

1. **CLI и интерактивный режим**  
   `cmd/browseragent/main.go` отвечает за парсинг флагов, загрузку `.env`, запуск интерактивного меню (`start`/`exit`) и последующий вызов оркестратора. При наличии флага `-task` задание выполняется сразу, без диалога.

2. **Оркестратор**  
   `internal/agent/orchestrator.go` реализует цикл Plan-and-Execute: формирование состояния (`planner.State`), запрос к LLM, запуск выбранного инструмента, сохранение шага в памяти и вывод результата в формате чата.

3. **Планировщик**  
   `internal/agent/planner/planner.go` содержит системный prompt и обработку JSON-ответа LLM (`thought`, `action`, `finish`). Планировщик проверяет корректность данных и сообщает оркестратору, завершать ли задачу.

4. **Инструменты и браузер**  
   - `internal/tools/toolbox.go` описывает универсальные инструменты (`navigate`, `click`, `fill`, `read_page`, `collect_links`, `add_note`, `request_user_input` и др.).  
   - `internal/browser/browser.go` — обёртка над Playwright: запуск Chromium, управление вкладкой, работа со storage state. Здесь нет жёстко захардкоженных селекторов — только общие действия.

5. **Память**  
   `internal/memory/memory.go` — потокобезопасное хранилище истории шагов. Сохранённые мысли, действия и наблюдения возвращаются планировщику и используются при логировании.

6. **Клиент LLM**  
   `internal/llm/client.go` — HTTP-клиент Anthropic Claude: чтение ключа, настройка модели, ретраи на 5xx/сетевые ошибки и разбор ответа. При необходимости провайдера можно заменить, изменив только этот модуль.

7. **Связка компонентов**  
   CLI → Оркестратор → Планировщик → LLM → Toolbox → Playwright → Память/лог. При `finish=true` агент выводит финальное резюме; при ошибках пробует другие стратегии или запрашивает ввод пользователя.

## Как я обошёл ошибку 429

На ограниченном ключе Anthropic Sonnet я упирался в лимит ~5 запросов/минуту и стабильно ловил `LLM вернул код 429`. Чтобы агент не падал, я разделил решение на две части: во‑первых, принудительно торможу между запросами; во‑вторых, автоматически делаю «паузу и повтор» после 429. Всё находится в `internal/agent/orchestrator.go`.

### 1. Кулдаун перед запросом

```go
const (
	defaultPlannerInterval   = 8 * time.Second
	plannerIntervalEnv       = "PLANNER_MIN_INTERVAL_SECONDS"
	minPlannerIntervalBounds = 1 * time.Second
)

var (
	minPlannerInterval = loadPlannerInterval()
)
```

- По умолчанию между вызовами LLM выдерживается 8 секунд.
- Чтобы сдвинуть интервал, достаточно экспортировать переменную:

  ```bash
  export PLANNER_MIN_INTERVAL_SECONDS=10  # или 6, если ключ позволяет
  ./browseragent -task "..."
  ```

Функция `waitPlannerCooldown` сравнивает `time.Since(lastPlannerCall)` и дожидается нужное количество секунд перед следующим шагом.

### 2. Повтор после 429

```go
nextDecision, err := o.planner.Next(ctx, state)
o.lastPlannerCall = time.Now()
if err == nil {
	decision = nextDecision
	break
}

if isRateLimitError(err) {
	o.logger.Warn().
		Err(err).
		Int("step", step).
		Msg("получен ответ 429 от LLM, ждём и повторяем попытку")
	if err := o.waitExtra(ctx, rateLimitBackoff); err != nil {
		return fmt.Errorf("ожидание после 429 прервано: %w", err)
	}
	continue
}
```

- `rateLimitBackoff` фиксирован в `12 * time.Second`.
- Любая ошибка с текстом `код 429` приводит к предупреждению в лог, дополнительному `waitExtra`, и только потом к повтору того же шага.
